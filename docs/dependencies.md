## 0. 版本方案：CalVer（`YY.MM.PATCH`）

- 本包版本用 CalVer，如 `26.9.0`，首版即 `26.9.0`（2026 年 9 月）。
- Cargo 只接受 semver 格式的字符串，`26.9.0` 恰好合法，可直接写 `version`。
  副作用：`^26.9.0` 按 semver 语义等于 `>=26.9.0, <27.0.0`（年内自动升），
  按年切大版本正好对应，可以接受。
- 第三方依赖保持 semver 原样；`Cargo.lock` 入库。
- 钉版：`mozjs` 用 `=` 精确钉（铁律）；其余 caret + lock，
  逐个 `cargo update -p <包>` 升级，禁全量 `cargo update`。

## 1. 目标矩阵（11 列）

| 短列名 | 完整 triple |
|---|---|
| `macA64` | `aarch64-apple-darwin` |
| `macX64` | `x86_64-apple-darwin` |
| `linA64` | `aarch64-unknown-linux-gnu` |
| `linX64` | `x86_64-unknown-linux-gnu` |
| `winA64` | `aarch64-pc-windows-msvc` |
| `winX64` | `x86_64-pc-windows-msvc` |
| `andA64` | `aarch64-linux-android` |
| `andV7` | `armv7-linux-androideabi` |
| `andX64` | `x86_64-linux-android` |
| `ohA64` | `aarch64-unknown-linux-ohos` |
| `ohX64` | `x86_64-unknown-linux-ohos` |

符号：✅=有证据支持；⚠️=存疑/待 CI 验证；❌=明确不支持。
WASI（`wasip1/wasip2`）永不进矩阵：各 crate 的 wasi cfg 分支是惰性的，不进 CI 即无影响。
过程宏（derive 类）只跑在 host，11 列天然全 ✅。

核心证据（2026-09-09 实测）：`rustc --print cfg --target aarch64-unknown-linux-ohos`
给出 `target_os="linux"`、`target_family="unix"`、小端——OHOS 自动命中全生态的
Linux/unix/小端分支。`getrandom` 官方支持表行 `*-linux-*` 覆盖 OHOS；
`tokio`/`mio` 官方保证 Linux/macOS/Windows/FreeBSD/iOS/Android（API 21+），OHOS 走同一 epoll 路径；
`mozjs-sys 153.0.0-1` 的 release 附件自带 11 个 triple 全套预构建包。

## 10. 含 C 依赖说明（zstd / rusqlite / ring / jemalloc）

- 四者都是 C（或 C+asm）经 `cc` 编译＋预生成 bindings，
  **默认不跑 bindgen、不需要 libclang/cmake**，只要目标镜像有 C 工具链
  （Xcode clang / MSVC / gcc / NDK，CI 默认自带）。
- zstd：上游 CI 覆盖 linux/windows/macos；Windows 自动关 ASM；
  musl 需配对 musl 版 C 工具链（常规要求）。
- rusqlite bundled：编入 SQLite 3.53.2 amalgamation，build.rs 对
  android/Windows/Apple 有显式分支；Android 即 AOSP 同款，无风险。
- ring（经 rustls 间接）：aarch64/armv7/x86_64 全覆盖。
- jemalloc：仅 linux/mac 生效，Windows/MSVC 自动回退系统分配器（cfg 门控）。
- 结论：与 AGENTS.md §6 不冲突（禁的是新增 C++/bindgen 痛苦，
  C-via-cc 可移植）；musl/iOS 以后加也只是 C 工具链问题。

## 11. 剩下必须手写的（轮子到头的地方，刻意保持小）

- mozjs 边界胶水（rooting、`AutoRealm`、FFI 调用，§6 允许的唯一 `unsafe` 区）。
- event-loop drain 编排（microtask/macrotask 调度本身，禁 `&mut` 别名）。
- ESM link/instantiate 编排（resolve 归 `oxc_resolver`，转译归 `oxc`，中间的拼装手写）。
- streams 引擎实现（挂在 mozjs 对象上，无轮子）。
- 测试 reporter 的 JS 侧 harness（输出 diff 复用 `similar`）。
- npm registry 客户端胶水（传输归 `reqwest`，寻址归 `deno_semver`，校验归 `ssri`，
  缓存布局归 `dirs`+`blake3`+`fs4`，解包归 `tar`+`flate2`）。
- URLPattern 路由匹配（`url` 之上的小状态机；serve 内部路由直接用 axum）。
- SSE（`hyper` Body 上约 30 行）；`bin` 链接（symlink 约 20 行）；
  NO_COLOR/TTY 判断（`std::io::IsTerminal`，稳定，无需依赖）。

## 12. 明确不引

- `dotenvy`（23 年后未更，用 `config` 替）、`swc_core`（选了 oxc）、

  头常量先用 hyper 的）、`simdutf` 类再绑一份 C++ 的做法（与 §6 冲突）。
- `wasmtime`（WASM 由 SpiderMonkey 引擎自己执行，不需要第二个运行时）。
- `openssl`/`native-tls`（全线 rustls，躲开 Windows 的 VCPKG/OpenSSL 地狱）。
- `async-trait`（原生 async trait 已稳定）、`mimalloc`（jemalloc 已选其一）、
  `redb`（sqlite 已选其一）、`compact_str`（`smol_str` 已选其一）、
  `tokio-tar`（`spawn_blocking` + `tar` 足够）、`jsonwebtoken`（用户态需求）。
